# 变更清单（llm-bench-docker → llm-bench-fix）

> 依据：目标机实测（worker-gpu-a，2026-11-05 采集）
> 驱动 570.172.08 / nvidia-smi CUDA 12.8 / ALinux3 / kernel 5.10.134-13.al8 /
> H200×8 143771 MiB（140.4 GiB）/ NV18 / RoCE（Ethernet 链路层）/
> **无 docker，有 containerd 1.6.28 + nerdctl** / toolkit 1.2.0 / 无 nvidia runtime 注册。
>
> 原始目录 `llm-bench-docker` 一个字节都没改。
> 引擎策略：**docker 优先，没有可用 docker 时回落 nerdctl**（目标机当前只有 nerdctl）；两种都支持。

分级口径：
- **P0** = 不改就跑不出正确结果（会卡死、会拿坏容器跑一整夜、或数字不可归因）
- **P1** = 能跑但结论不可信/不可复现（指纹缺失、假跳过、口径不一致、硬件验收缺项）
- **P2** = 文档与可读性（不影响执行，影响评审）

## 附：NCCL_IB_HCA 的写法说明

NCCL 只接受逗号分隔的设备名，不认识 `mlx5_bond_2..9` 这种区间语法。所以脚本用等价的展开形式：

```
NCCL_HCA="${NCCL_HCA:-mlx5_bond_2,mlx5_bond_3,mlx5_bond_4,mlx5_bond_5,mlx5_bond_6,mlx5_bond_7,mlx5_bond_8,mlx5_bond_9}"
```

设备名以实测的 `/sys/class/infiniband` 为准（拓扑图 legend 里 NIC0-9 对应 `mlx5_bond_0..9`，
其中 `bond0`/`bond1` 是管理口，RoCE 用 `bond2..9`）。`NCCL_IB_GID_INDEX` 默认 3（RoCEv2 常见值），
如果建链失败，用 `show_gids`（Mellanox OFED）或 `ibv_devinfo -v | grep GID` 查实际 RoCEv2 索引后覆盖：
`NCCL_GID=<实际索引> bash 04_bench.sh --phase dx8b`。

## 本轮追加：容器引擎策略（docker 优先 / nerdctl 兼容）

目标机当前只有 nerdctl，但方案要求以 docker 为主，因此两种引擎都要能跑。

| # | 项 | 改成什么 | 对应文件 |
|---|---|---|---|
| P2-18 | 引擎写死 nerdctl，无法在装了 docker 的机器上复用 | `lc_init()` 自动探测：默认 `docker → nerdctl`；只有 `docker version`（daemon 通）才采用 docker；`ENGINE=nerdctl` 可显式覆盖；两者都没有时报错并给两条修复路径（装 docker / 用 nerdctl） | `lib.sh`、`preflight.sh` |

### 已知差异（写进报告限制声明）

- **GPU 注入路径不同**：docker 的 `--gpus all` 依赖已注册的 **nvidia runtime**（`docker info` 的 `Runtimes` 必须含 `nvidia`）；nerdctl 走 **CDI / nvidia-container-cli OCI hook**。同一张卡、同一个镜像，两个引擎的注入实现不同，失败时先按上面的「引擎问题 / toolkit 问题」两类分开排查。
- **镜像 digest 取值方式不同**：docker 优先 `images --digests` / `RepoDigests`；nerdctl 的格式化占位符兼容性因版本而异，取不到时回退 `image inspect` 的 config ID。因此报告里 **以 digest 为准**，同一 digest 才可跨机、跨引擎比较；只有 config ID 时要在限制声明里注明。
- **load 与 run 必须同命名空间（仅 nerdctl）**：load 到 `default`、run 到 `k8s.io` 会表现为「镜像不存在」；脚本已固定 default 并拒绝 `k8s.io/moby`。docker 无此约束。
- **不要把两台机器配成不同引擎**：engine/namespace 已进指纹；双机混用会导致 NCCL 版本与注入路径不同，D1 比值不可比。
